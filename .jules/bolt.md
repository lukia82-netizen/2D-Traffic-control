## 2025-02-18 - Optimized VehicleRenderer performance with O(1) road group cache, bounds hoisting, and zero-allocation project coordinates
**Learning:** High-frequency per-frame rendering loops in PixiJS/MapLibre simulation setups suffer from O(E) spatial lookups, redundant getter method invocations, and garbage collection pressure due to temporary coordinate array allocations. Inlining coordinate structures and resolving static maps on map data load drastically improves performance and reduces CPU overhead.
**Action:** Always pre-calculate static mappings (like lane IDs to road groups) on initial map data load, hoist Map bounds getters out of high-frequency loops, and pass existing compatible entity objects directly to MapLibre's `project` method to avoid new object allocations.
