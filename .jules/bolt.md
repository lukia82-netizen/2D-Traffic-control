## 2025-02-28 - [High-Frequency Frame Loop Allocations and Spatial Searches in VehicleRenderer]
**Learning:** In high-frequency render loops (e.g., 60 FPS under PixiJS and MapLibre), allocating object wrappers or temporary coordinate arrays (like `[lng, lat]`) creates severe garbage collection pressure and CPU overhead. By passing `VehicleState` directly to MapLibre's `project` (which natively accepts any `LngLatLike` objects containing `lng` and `lat` properties), we eliminate these temporary array allocations entirely. Furthermore, hoisting expensive MapLibre bounds function calls outside the rendering loop avoids redundant boundary evaluation. Finally, caching the road group of static lanes (`laneGroupCache`) enables a fallback-free O(1) road-group lookup in `isVehicleHidden`, bypassing O(E) spatial searches.
**Action:** Always inspect frame loops for temporary array allocations, function-call getters that can be hoisted, and opportunity to pre-cache hierarchical domain relationships (like lanes-to-road-groups) to avoid spatial searches in high-performance rendering paths.
