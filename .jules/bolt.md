## 2025-05-18 - O(1) Lane-to-Road-Group Mapping & Loop Optimization in VehicleRenderer
**Learning:** Checking road-group visibility per vehicle via spatial distance searches (`resolveVehicleGroup`) introduces $O(E)$ overhead per moving vehicle at 60 FPS. Leveraging `currentLaneId` in `VehicleState` mapped to pre-calculated `laneGroupCache` during map load converts this check to $O(1)$ time complexity, saving substantial CPU time when rendering thousands of vehicles. Additionally, extracting static viewport geographic bounds (`west`, `east`, `south`, `north`) before starting per-entity rendering loops prevents thousands of redundant `LngLatBounds` method calls per frame, while reusing a class-level Set for rendered vehicle IDs eliminates per-frame allocations.
**Action:** When filtering entities by static map attributes in high-frequency render loops, pre-compute ID-to-attribute lookup maps during data setup rather than using spatial searches at runtime, and hoist invariant property accesses outside hot iteration loops.
