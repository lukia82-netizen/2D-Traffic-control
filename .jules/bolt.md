## 2026-05-10 - [MapRenderer viewport culling optimization]
**Learning:** High-frequency rendering loops hooked to MapLibre's `'render'` event (e.g. `RoadRenderer`, `BuildingRenderer`, `TrafficLightRenderer`, `InfraRenderer`) are executed constantly during zoom, pan, and transition events. Projecting coordinates via `map.project` and generating PixiJS shapes for entities that are completely off-screen wastes significant CPU cycles and triggers frequent Garbage Collection. Implementing cheap O(1) coordinate-based bounding box culling (with a small 5-10% padding to prevent clipping) before calling `projectPoint` or drawing graphics dramatically reduces CPU rendering overhead and provides extremely smooth, high-frame-rate navigation.
**Action:** Always check if static map elements (roads, buildings, lights, markings) are within the visible viewport bounds before performing expensive projections or PixiJS object instantiation/rendering in event-driven map overlays.
