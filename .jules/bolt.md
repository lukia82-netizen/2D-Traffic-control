## 2025-02-18 - Avoid Spatial O(E) Segment Distance Search in High-Frequency Rendering Loops
**Learning:** Performing O(E) spatial segment distance checks for every moving vehicle on every frame to resolve road-group filtering (isVehicleHidden) causes massive CPU overhead, especially with high vehicle counts. The vehicle state event carries `currentLaneId` which can be mapped to road groups in O(1) via a pre-computed map of lane node OSM IDs.
**Action:** Use a pre-computed `laneGroupCache` during map initialization (`setEdgeIndex`) to map lane IDs to road groups in O(1). Fall back to the O(E) search only when `currentLaneId` is missing or fails cache lookup. Additionally, hoisting Map bounds getter methods outside per-vehicle rendering loops and avoiding temporary coordinate array allocations reduces GC and CPU overhead.
