## 2025-02-13 - O(1) Lane Group Caching and Map Bounds Hoisting
**Learning:** Hoisting Map bounds getter methods (`bounds.getWest()`, `bounds.getEast()`, `bounds.getSouth()`, `bounds.getNorth()`) outside high-frequency rendering loops prevents redundant function calls on every frame per vehicle. Additionally, replacing O(E) spatial searches for road-group filtering with O(1) lookups using a pre-computed cache (mapping lane IDs to road groups via edge node OSM IDs) significantly reduces per-frame CPU usage, falling back to spatial searches on connector lanes. Passing `VehicleState` or compatible entities directly to MapLibre's `project` method instead of allocating coordinate arrays `[lng, lat]` also reduces Garbage Collection pressure in high-frequency rendering loops.
**Action:** Always hoist map bounds and scale factors, pre-compute static associations (like lane-to-group or edge-to-group) into O(1) caches during data load/set stages, and pass native objects directly to projection APIs to avoid array allocation overhead.
