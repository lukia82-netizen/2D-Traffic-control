## 2026-06-26 - Optimize Vehicle Rendering with O(1) Lookups and API Hoisting
**Learning:** High-frequency rendering loops (60 FPS) are extremely sensitive to API calls and temporary allocations. Hoisting `map.getBounds()` and its coordinate getters, along with avoiding `[lng, lat]` array literals for `map.project()`, significantly reduces CPU overhead. Furthermore, replacing O(E) spatial searches for road-group filtering with O(1) lookups using a pre-computed cache (mapping lane IDs to road groups) provides a massive performance boost as the number of vehicles and edges grows.
**Action:** Always hoist expensive API calls and constant values out of per-entity loops. Minimize allocation of temporary objects/arrays in hot paths. Utilize available unique identifiers (like `currentLaneId`) for constant-time data lookups instead of spatial searches.
