## 2026-07-26 - [High-Frequency Vehicle Rendering Optimization]
**Learning:** In highly nested animation/rendering loops (60 FPS), small repeated calculations like extracting map bounds (`map.getBounds()`), getting corners (`getWest()`, `getEast()`, `getSouth()`, `getNorth()`), or allocating temporary coordinate arrays `[lng, lat]` can create significant CPU overhead and trigger frequent garbage collection sweeps. Moreover, sequential O(E) spatial searches performed on every frame for filtering hidden vehicles can block the main thread completely when there are thousands of vehicles. Pre-computing lane-to-road group mappings and caching them in an O(1) Map lookup completely eliminates this bottleneck.
**Action:** Always hoist bounds-getters and map projection scaling outside of per-entity loops. Pass native compatible data structures (like `SmoothState` with `lng` and `lat` fields) directly to libraries like MapLibre GL `project()` to prevent temporary array allocations, and build pre-computed cache mappings (O(1)) during data initialization.
